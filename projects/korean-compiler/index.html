한국어 문장이 코드로 바뀌는 과정

한국어 키워드로 작성한 문장을 토큰으로 나누고, 문법에 맞는 구문 트리를 만든 뒤 스택 기반 명령을 생성하는 과제입니다. 연산자 하나를 추가할 때에도 어휘 분석, 문법 규칙, 코드 생성의 여러 단계를 연결해야 한다는 점을 살펴볼 수 있습니다.

기반은 수업용 CBU 샘플 컴파일러입니다. 소스의 출처 표기에는 Jae Sung Lee, 2022가 명시돼 있습니다. 이 프로젝트에서는 README의 개발 기록과 cbu2.l·cbu2.y에 남아 있는 산술 연산, 한국어 비교·반복 표현, 출력과 증감 연산 확장을 소개합니다.

문법 파일에서 확인할 수 있는 기능

산술 연산과 우선순위

더하기 · 빼기 · 곱하기 · 나누기 / + − * /

expr → term → factor로 문법을 나눠 곱셈·나눗셈이 덧셈·뺄셈보다 먼저 묶이도록 구성했습니다.

한국어 조건문

만일 가 는 나 보다 크거나같다면 … 이다

비교 연산 여섯 가지를 토큰과 문법 규칙으로 연결하고, 조건에 따라 분기 명령과 종료 레이블을 생성합니다.

조건 기반 반복문

i 는 10 보다 작은 동안 … 반복한다

조건 검사와 본문을 구문 트리로 만들고, 반복 시작·탈출 레이블 및 되돌아가는 분기 명령을 출력합니다.

증감·복합 대입

++ · -- · += · -= · *= · /=

변수의 주소와 현재 값을 스택에 올린 뒤 연산 결과를 대입하는 코드 생성 규칙을 추가했습니다.

숫자 출력

출력 변수명; / 출력 숫자;

PRINT factor 규칙을 통해 변수나 정수를 출력하는 OUTNUM 명령을 생성합니다.

구현에서 연결한 세 가지 지점

1. 한국어 표현을 같은 연산 토큰으로 묶기

어휘 분석 규칙에서는 곱하기와 *를 모두 MUL로, 나누기와 /를 모두 DIV로 연결합니다. 이후 구문 분석기는 표현이 한국어였는지 기호였는지에 관계없이 같은 연산 규칙을 사용할 수 있습니다.

2. 문법의 층으로 연산자 우선순위 표현하기

덧셈·뺄셈을 expr, 곱셈·나눗셈을 term, 변수·숫자를 factor로 나눕니다. 예제의 가 더하기 20 곱하기 2에서 곱셈이 먼저 묶이는 구조입니다.

expr   : expr ADD term | expr SUB term | term
term   : term MUL factor | term DIV factor | factor
factor : ID | NUM

3. 구문 트리를 스택 명령으로 바꾸기

MakeOPTree와 MakeListTree로 만든 트리를 DFSTree로 순회하고 prtcode에서 명령을 출력합니다. 조건문과 반복문에서는 레이블 번호를 스택에 보관해 분기와 탈출 지점을 연결합니다.

SOURCE EXPRESSION

나:=가 더하기 20 곱하기 2;

오른쪽은 이 문장에 코드 생성 규칙을 적용해 읽은 명령 예시입니다. 변수 주소를 먼저 올리고, 곱셈·덧셈을 계산한 결과를 대입합니다.

빌드 구성을 확인할 때

  • 저장소에는 Visual Studio 프로젝트와 win_flex·win_bison 호출용 배치 파일이 있습니다. 명령은 각각 flex.bat cbu2, bison.bat cbu2 형태이며, 문법 변경 후에는 Bison으로 헤더·파서를 만든 다음 Flex로 스캐너를 생성하는 순서로 확인할 수 있습니다.
  • cbu2.l과 예제의 한글은 CP949로 읽히며, 한글 식별자 규칙도 2바이트 문자 범위를 사용합니다. 문자 인코딩과 스캐너의 문자 처리 규칙을 함께 확인해야 합니다.
  • 저장된 cbu2.c·cbu2.h에는 최신 cbu2.y와 토큰 차이가 있어, 최신 문법으로 빌드하려면 생성 파일을 다시 만들어야 합니다. 이 페이지의 기능 설명은 문법·예제 소스 기준입니다.
