클라우드 자원 관리와 원격 상태 조회를 한곳에서

EC2 인스턴스를 조회하거나 시작·중지하고, 작업 노드의 이미지를 보관하는 일을 Java 콘솔 메뉴로 연결한 클라우드 컴퓨팅 수업 프로젝트입니다. 소스에는 Dynamic Resource Management Tool이라는 설명이 남아 있습니다.

자원 생성·제어에는 AWS SDK의 EC2 API를 사용하고, Condor 상태 확인에는 인스턴스의 공인 DNS를 알아낸 뒤 SSH로 원격 명령을 실행합니다. 클라우드 API와 운영체제 프로세스를 연결해 관리 작업의 입력·처리·결과 표시를 구성했습니다.

RESOURCE CONTROL

Java 콘솔 → AWS SDK → EC2

인스턴스·리전·가용 영역·AMI 조회 및 제어

원본 소스의 메뉴 구성 보기
Amazon AWS Control Panel using SDK

 1. list instance        2. available zones
 3. start instance       4. available regions
 5. stop instance        6. create instance
 7. reboot instance      8. list images
 9. condor status       10. create slave image

소스에 정의된 메뉴 문구를 정리한 것으로, 실제 AWS 연결 결과를 캡처한 화면은 아닙니다.

01

인스턴스 목록

listInstances()

인스턴스 ID·AMI·유형·상태·모니터링 상태를 조회하고 nextToken으로 다음 페이지를 읽습니다.

02

가용 영역 조회

availableZones()

접근 가능한 가용 영역의 ID·리전·영역 이름을 출력합니다.

03

인스턴스 시작

startInstance()

입력한 인스턴스 ID로 StartInstances 요청을 보냅니다.

04

리전 조회

availableRegions()

리전 이름과 엔드포인트를 조회합니다.

05

인스턴스 중지

stopInstance()

입력한 인스턴스 ID로 StopInstances 요청을 보냅니다.

06

인스턴스 생성

createInstance()

선택한 AMI로 t2.micro 인스턴스 1개를 생성합니다. 보안 그룹·키 페어·Base64 인코딩한 User Data를 설정합니다.

07

인스턴스 재부팅

rebootInstance()

입력한 인스턴스 ID로 RebootInstances 요청을 보냅니다.

08

AMI 목록

listImages()

소유자 ID 필터로 AMI를 조회해 이미지 ID·이름·소유자를 출력합니다.

09

Condor 상태 조회

condorStatus()

EC2의 공인 DNS를 조회한 뒤 로컬 ssh 프로세스로 condor_status를 실행하고 표준 출력과 종료 코드를 읽습니다.

10

작업 노드 AMI 생성

createSlaveImage()

인스턴스에서 AMI를 만들고 15초 간격으로 상태를 조회해 available이 될 때까지 기다립니다.

구현에서 연결한 흐름

1. 인스턴스 목록을 끝까지 조회하기

DescribeInstancesRequest로 예약 정보와 인스턴스 목록을 읽고, 응답의 nextToken을 다음 요청에 넣습니다. 토큰이 더 이상 없을 때 반복을 마치므로 첫 페이지만 표시하는 대신 여러 페이지의 자원을 확인할 수 있습니다.

2. AMI에서 관리할 인스턴스 만들기

createInstance()는 입력한 AMI를 바탕으로 인스턴스 유형과 생성 개수를 정하고, User Data·보안 그룹·키 페어를 함께 전달합니다. User Data는 시작 시 수행할 스크립트를 Base64로 인코딩해 요청에 포함하는 방식입니다.

원본은 특정 실습 환경의 설정을 사용합니다. 다시 사용할 때는 AMI·리전·보안 그룹·키 페어·접속 사용자를 사용할 환경에 맞춰 준비해야 합니다.

3. EC2 인스턴스 ID를 SSH 접속 대상으로 연결하기

  1. 입력받은 인스턴스 ID로 EC2 정보를 조회합니다.
  2. getPublicDnsName()으로 원격 호스트를 얻습니다.
  3. 접속 사용자와 키 경로를 조합해 로컬 ssh 프로세스를 실행합니다.
  4. 원격 condor_status의 표준 출력을 읽고, 프로세스가 종료되면 종료 코드를 표시합니다.

이 경로에는 SSH로 접속 가능한 인스턴스와 해당 환경의 Condor 구성이 필요합니다. 소스에 구현된 범위는 원격 상태 조회이며, 작업 제출이나 자동 스케일링은 별도 확장 주제입니다.

4. 작업 노드를 재사용할 AMI로 보관하기

createSlaveImage()는 인스턴스 ID와 이미지 이름으로 AMI 생성을 요청합니다. 생성 요청에는 withNoReboot(true)가 설정돼 있으며, 응답으로 받은 이미지 ID를 기준으로 상태를 15초 간격으로 확인합니다. available 상태가 되면 대기 반복을 마칩니다.

대상 인스턴스→AMI 생성 요청→상태 재조회→available

실행 환경과 이어 개선할 부분

  • 원본은 com.amazonaws 패키지의 AWS SDK for Java 1.x와 로컬 AWS 자격 증명 프로필, 시스템의 SSH 명령을 사용하는 구성입니다.
  • 초기화 메서드는 리전을 명시하지만 여러 작업 메서드는 기본 클라이언트를 별도로 생성합니다. 재사용 시 리전·인증 설정을 일관되게 적용하는 구성을 검토할 수 있습니다.
  • AMI 대기는 available이 될 때까지 반복하는 형태입니다. 대기 시간 상한과 실패 상태 분기, SSH 오류 출력 처리 등을 더하면 운영 중 문제를 구분하기 쉬워집니다.

이 페이지는 저장소의 코드와 개발 기록을 바탕으로 정리했습니다. AWS 자원을 생성·제어하거나 원격 인스턴스에 접속해 재실행한 결과는 포함하지 않습니다.
